# 一致 · 内容口径校对

这是一个可独立运行的内部校对工具。它保留了原型的上传页、问题清单、风险筛选、证据查看和 CSV 导出，并补齐了文档、图片 OCR 与本地音视频转写链路。

## 本次修复了什么

原型页面能正常显示，但上传按钮最终依赖 `/api/tasks` 完成文件解析和跨文件比对。当前代码包如果没有配套后端，就只能停留在“选择文件”和“开始检测”，无法生成真实结果。

本次修复完成了以下闭环：

- 解析 PPTX、DOCX、PDF、TXT、MD、CSV 的文字层。
- 图片上传后使用本地 Tesseract 中文 OCR；支持 PNG、JPG、WEBP、BMP、TIFF。
- 视频和音频上传后使用 FFmpeg 抽取音轨，再由内置 Whisper Tiny 模型在本机转写；支持 MP4、MOV、MKV、WEBM、AVI、MP3、M4A、WAV、AAC、FLAC、OGG、OPUS。
- 校验至少两份**可读取**的物料；不足两份时明确报错，避免把解析失败误显示成“无冲突”。
- 检查食材名对应剂量、数值与单位、推荐/禁忌、适用范围、相反操作方向五类冲突。
- 食材剂量不依赖整句相似度：即使讲义是“广陈皮8克”，逐字稿是“广陈皮咱们用2～4克”，也会按食材名对齐。
- 强制抽取结构化事实卡：对象、属性、关系、数值/单位、时间类型、人群、条件、顺序、倾向和来源必须齐全，缺失字段的事实不参与判断。
- 区分总烹饪、后下、单次练习、课程周期和食用周期五类时间；检查单份材料内部与跨材料的顺序、时间和概念冲突。
- 检查食材“四气、五味、归经”，支持微寒/微温等表述，并把归经和五味的书写顺序视为等价。
- 检查同课材料的操作名、结构名称和结构数量；操作名相近但不一致时归为低危，可单独筛选。
- 把“6天体验营、5天训练营”等营期天数归为课程周期，不与其他时间类型混用。
- 检查穴位操作方向缺失或相反，并把作业答案解析与视频课程原文交叉核对。
- 后台案例库记录方向缺失、方向冲突、外部来源不确定、作业答案冲突和跨版本重复错误；认证后可通过 `/api/cases` 查看。
- 每个任务只保存并分析本次上传的文档对象；提交成功、点击新建或浏览器返回上传页时都会强制清空旧文件和控制台状态。
- 公网测试隧道返回 `502 no tunnel` 时，界面会明确提示“测试通道已断开”，不再误报成文档检测失败。
- 浏览器出现底层 `Failed to fetch` 时，界面会明确提示公网隧道或网络已中断，并给出本机可用入口。
- 文件上传后立即返回后台任务编号，浏览器通过短轮询获取转写和比对进度，避免隧道因长连接等待返回 408/502。
- 后台任务按队列串行执行，任务完成后自动清理上传临时文件。
- 来源信息升级为独立的大号定位卡，优先展示文件名、模态和页码/OCR位置。
- 风险视觉统一为高危红、中危黄、低危蓝，并在卡片顶部与左侧边框强化区分。
- OCR 会保存每行文字框，并在问题卡和证据弹层显示对应原图局部截图。
- 结果页和 CSV 中可查看事实卡字段，便于复核 AI 为什么判为冲突。
- 将结果定位到具体文件、页码或段落，并保留两侧原文证据。
- 支持待处理、确认、误报、忽略四种状态，刷新后仍保留到服务重启。
- 支持 UTF-8 CSV 导出。
- 增加口令门、上传限制、任务 7 天失效和内存态存储。

## 运行

需要 Node.js 22.3 或更高版本，推荐 Node.js 24；视频转写需要系统可用的 `ffmpeg` 与 `ffprobe`。

```powershell
cd D:\Codex\2026-10-21\new-chat\outputs\yizhi-proofreader
npm ci
$env:ACCESS_CODE = "yizhi2026"
npm start
```

打开 `http://localhost:3000`。

默认不启用访问口令，所有获得链接的人都可以直接使用。如仍需保护，可通过 `ACCESS_CODE` 环境变量重新开启口令门。

公开模式下，任何获得链接的人都可以上传材料并查看当前任务列表；请不要上传未获授权的敏感课程、个人信息或未公开资料。

可配置项：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务端口 |
| `ACCESS_CODE` | 空 | 访问口令；留空时所有获得链接的人都可以使用 |
| `TASK_TTL_DAYS` | `7` | 任务保留天数 |
| `NODE_ENV` | 未设置 | 设为 `production` 时 cookie 强制使用 `Secure`，需要 HTTPS |

## Docker 部署

```bash
docker build -t yizhi-proofreader .
docker run --rm -p 3000:3000 -e ACCESS_CODE='替换为强口令' -e NODE_ENV=production yizhi-proofreader
```

部署到 WorkBuddy 或其他平台时，需要选择**可运行 Node 服务的全栈环境**。只部署静态页面无法完成文档解析和比对。

Docker 镜像已包含 FFmpeg。本地 Whisper 模型随 npm 依赖安装，不需要 API Key，也不需要首次运行时下载模型。

## 文件处理边界

- 文档最大 80MB、图片最大 20MB、音视频最大 300MB，单次最多 8 个文件，总大小最大 500MB。
- 扫描件 PDF 没有文字层时无法提取，需要先 OCR。
- 老版 `.ppt` / `.doc` 需要另存为 `.pptx` / `.docx`。
- 视频转写使用轻量 Whisper Tiny 模型，中文口播可获得可用底稿，但专业术语、人名和方言仍需人工复核；当前不支持说话人分离。
- 音视频最长 2 小时，转写耗时取决于 CPU 性能。
- PPTX 读取幻灯片文本框；图表内嵌数据、SmartArt 中未被正常导出的文字可能需要人工复核。
- 当前规则帮助发现明确冲突，不会替代医学、法律、合规或课程内容的最终人工判断。
